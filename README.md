# Танцевальная революция

Сайт на React и Vite, собственная админ-панель и сервер Node.js. Новости, настройки, учётные записи и сессии хранятся в SQLite; фотографии и документы — на диске того же сервера. Вход по логину и паролю. GitHub, OAuth, отдельная CMS и облачная база не нужны.

## Первый запуск

Нужен **Node.js 24+** с модулем `node:sqlite`. Все команды запускайте из папки проекта.

```sh
npm ci
npm run admin:create
npm run build
npm start
```

Команда `admin:create` спросит логин и пароль в терминале. Пароль не отображается и хранится только в виде хеша scrypt. Минимальная длина — 12 символов. Общего или стандартного пароля нет. Сайт откроется на `http://127.0.0.1:3000`, редактор — `http://127.0.0.1:3000/admin/`.

В Windows PowerShell при запрете `npm.ps1` используйте `npm.cmd` вместо `npm`, например `npm.cmd run admin:create`.

```sh
npm run dev             # разработка с горячим обновлением
npm run preview         # локальный просмотр сборки вместе с API
npm run admin:password  # смена пароля существующего администратора
npm run check           # серверные тесты и сборка
npm run test:e2e        # проверка сайта и редактора в Google Chrome
```

`dev`, `preview`, `start` и команды администратора используют одну папку данных. Для другого расположения задайте `DATA_DIR`. Браузерные и серверные тесты используют временные базы: реальные публикации и учётные записи не изменяются, письма не отправляются.

## Работа в редакторе

1. Откройте `/admin/`, введите логин и пароль.
2. Нажмите «Новая публикация». Заполните заголовок, краткое описание, дату, рубрику и текст. Адрес автоматически предлагается из заголовка; до первого сохранения его можно изменить.
3. В каждом разделе можно указать подзаголовок. Абзацы разделяются пустой строкой. Обложка необязательна: JPG, PNG или WebP до 2 МБ; имя файла может быть любым.
4. «Сохранить черновик» сохраняет запись только в админке. «Предпросмотр» показывает её оформление. «Опубликовать» сразу делает запись доступной посетителям.
5. «Снять с публикации» возвращает запись в черновики. При редактировании опубликованной записи «Сохранить изменения» сразу обновляет страницу.

Сохранённый адрес статьи закреплён, чтобы не ломались ссылки. Дата — подпись материала, а не расписание отложенной публикации. При конфликте двух вкладок сервер отклоняет устаревшую версию вместо перезаписи чужих изменений. При завершении сессии несохранённый текст остаётся в текущей вкладке до повторного входа; закрытие или перезагрузка вкладки его удалит.

На главной показываются три последних публикации, список — `/news`, статьи — `/news/адрес`. Сервер сразу отдаёт HTML с текстом, title, description, canonical, Open Graph и Article JSON-LD. Для публикации или исправления статьи сборка и перезапуск не требуются. `/sitemap.xml` и `/robots.txt` формируются сервером. Пустая лента имеет `noindex` до первой публикации. Черновики исключены из публичных API, HTML и sitemap; загруженные изображения доступны без входа только пока используются опубликованной статьёй или сохранёнными настройками сайта.

Сессия длится 8 часов. После 10 попыток входа за 15 минут ограничивается вход для логина и IP. Смена пароля через `admin:password` закрывает существующие сессии этого пользователя. Публичной регистрации нет; дополнительные учётные записи создаются той же командой `admin:create` на сервере.

## Настройки сайта

В `/admin/` раздел **«Настройки сайта»** позволяет редактировать:

- даты начала и финала конкурса, заезда и выезда, сроки приёма заявок, город;
- стоимость участия и проживания, премию, стоимость и срок замены репертуара;
- название, адрес, описание, карту и фотографию площадки;
- гостиницу, фотографии гостиницы и номера, питание и транспорт;
- телефон, единый e-mail оргкомитета, часы работы, ссылки на Telegram, Instagram, VK, MAX и WhatsApp;
- названия и описания четырёх этапов программы;
- состав жюри: имена, должности, описания, фотографии и порядок карточек;
- страницы `/privacy` и `/consent`: заголовок, вступление, тексты и порядок разделов;
- страницу `/news`: заголовок, вступление и сообщение до первой публикации;
- положение конкурса: загрузка PDF или DOCX до 10 МБ.

Фотографии принимаются в JPG, PNG и WebP до 2 МБ. Нажмите **«Сохранить настройки»**, затем обновите страницу сайта. Сборка и перезапуск не требуются. Даты синхронизируются в hero, программе, условиях, форме, заголовке страницы и письмах; длительность проживания рассчитывается из дат заезда и выезда. Контакты также обновляются в письмах и страницах политики и согласия. Все ссылки на положение используют сохранённый файл.

Документы и новости формируются сервером из базы, отдельных HTML-файлов документов нет. Адреса `/privacy.html` и `/consent.html` перенаправляют на новые страницы. В текстах документов пустая строка начинает абзац; `{email}` и `{phone}` подставляют актуальные контакты, `{privacy}` и `{regulations}` — ссылки на политику и положение. Начальные тексты находятся в `shared/page-content.json`; после первого сохранения редактируйте их в админке.

Изображения из `public/assets` с прежним именем проверяются браузером через ETag. После замены файла при запуске через `npm start` выполните `npm run build` и перезапустите сервер. Для разработки используйте `npm run dev`.

Тексты программы не переписываются автоматически при смене дат; содержимое PDF/DOCX тоже не изменяется — загрузите актуальный документ. Все настройки публичные: не вводите в них пароли или ключи сервисов. Секреты отправки почты остаются в `.env.local`.

Редактор предупреждает о несохранённых изменениях. После истечения сессии они сохраняются в памяти открытой вкладки до повторного входа. При конфликте двух вкладок запись отклоняется: скопируйте нужный текст, нажмите «Загрузить сохранённую версию» и повторите правку. Закрытие вкладки удалит несохранённые изменения.

## Размещение на одном сервере

Нужен **VPS или хостинг с постоянно работающим Node.js и постоянным диском**. Обычная загрузка HTML на PHP-хостинг и прежняя схема Vercel Functions для этой версии не подходят. SQLite рассчитана на один сервер; не запускайте копии проекта с отдельными дисками или несколько реплик за балансировщиком.

1. Загрузите исходники, `package.json`, `package-lock.json`, папки `server`, `shared`, `content`, `public` и остальные файлы для сборки. Файл `public/assets/hero-video.mp4` исключён из Git — перенесите его отдельно до сборки. Без него останется фото-заставка.
2. Создайте постоянную папку данных вне каталога, который хостинг заменяет при обновлении, например `/var/lib/dance-revolution`. Дайте пользователю процесса права записи в неё.
3. Скопируйте `.env.example` в `.env.local` и задайте параметры. Не публикуйте этот файл:

   ```dotenv
   NODE_ENV=production
   SITE_URL=https://ваш-домен.ru
   HOST=127.0.0.1
   PORT=3000
   DATA_DIR=/var/lib/dance-revolution
   TRUST_PROXY=1
   ```

   `TRUST_PROXY=1` нужен только за доверенным обратным прокси. Сервер берёт последний адрес из `X-Forwarded-For`, поэтому прокси должен добавлять адрес клиента в конец заголовка. Прямой доступ к Node-порту извне должен быть закрыт. Без прокси оставьте `TRUST_PROXY` выключенным.

4. Выполните `npm ci`, `npm run admin:create`, `npm run build`. Настройте постоянный запуск команды `npm start` через панель хостинга или systemd/PM2. Не создавайте администратора заново при обычном обновлении.
5. Настройте HTTPS на домене и передачу **всех путей** сайта в Node.js на порт 3000. В рабочем режиме без `SITE_URL=https://...` сервер не запускается, а cookie администратора работает только по HTTPS.

Пример маршрутизации для существующего HTTPS-сервера nginx:

```nginx
client_max_body_size 12m;
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

TLS-сертификат и домен настраиваются в панели хостинга либо в конфигурации nginx отдельно. Не включайте общий кеш для HTML, `/admin/`, `/api/`, `/news`, `/media/` и `/documents/`: изменения настроек и снятие с публикации должны применяться сразу. `/health` возвращает `{"ok":true}`, когда сервер и база доступны.

При смене домена достаточно обновить `SITE_URL` и перезапустить процесс. Сервер подставляет его в canonical главной страницы, страницы статей и карту сайта.

## Данные, обновление и резервные копии

По умолчанию используется `.data/`:

```text
.data/
  site.sqlite      — настройки, публикации, хеши паролей, сессии и лимиты входа
  site.sqlite-wal  — рабочий журнал SQLite, если он существует
  site.sqlite-shm  — служебный файл SQLite, если он существует
  uploads/         — загруженные фотографии, обложки и положения
```

Вся папка исключена из Git. Она не входит в `dist` и не удаляется сборкой. При обновлении заменяют код и `dist`, сохраняя каталог `DATA_DIR`.

Для простой согласованной резервной копии остановите процесс Node, скопируйте **всю папку данных**, затем запустите процесс. Храните резервные копии вне публичных папок сайта. Для восстановления остановите сервер, верните полную копию в `DATA_DIR` и запустите его. Нельзя копировать только `site.sqlite` во время записи, игнорируя WAL-журнал.

Файлы из `content/news/` импортируются только при первом создании базы. Сейчас там один пример черновика. Последующие публикации сохраняются в SQLite; удалённые записи не восстанавливаются из файлов после перезапуска. Настройки создаются из `shared/site-settings.js` при миграции базы до версии 2. Миграция выполняется автоматически и сохраняет существующие статьи и учётные записи. Правка значений по умолчанию в коде не перезаписывает сохранённые настройки. Перед обновлением кода сделайте резервную копию базы.

Неиспользуемые загрузки остаются на диске, но посетителям недоступны. Файлы из `public/assets/` и `public/docs/` всегда публичные.

## Заявки и почта

Отправка заявок сохранена через Resend. Для неё отдельно заполните в `.env.local`:

- `RESEND_API_KEY` — ключ сервиса;
- `APPLICATION_TO_EMAIL` — необязательное переопределение получателя; без него используется e-mail оргкомитета из админки;
- `APPLICATION_FROM_EMAIL` — отправитель на подтверждённом домене.

Админка и новости работают без почтового ключа. Секреты остаются на сервере, не добавляйте к именам переменных префикс `VITE_`. Перезапускайте процесс после изменения переменных окружения.

Заявка передаётся двумя письмами: Оргкомитету и заявителю. Базы заявок в проекте нет. Форма принимает 5–500 участников, хронометраж до четырёх минут, требует принятие Положения, согласие на обработку персональных данных и список проживающих при выборе проживания. Перед публичным приёмом заявок настройте ограничение частоты запросов `/api/application` на стороне хостинга: скрытое поле ловит лишь простых ботов.

## Структура исходников

```text
src/sections/, src/components/ — сайт и форма заявки
src/admin/                    — React-редактор публикаций и настроек
src/SiteSettings.jsx           — общие настройки для секций сайта
admin/index.html              — входная HTML-страница редактора
src/styles.css                — дизайн сайта
server/index.js               — HTTP-сервер и статические файлы, включая видеодиапазоны
server/app.js                 — API, проверка доступа, страницы новостей и документов
server/auth.js                — пароли, сессии и ограничение попыток входа
server/database.js            — SQLite и импорт начальных материалов
server/admin-cli.js           — создание администратора и смена пароля
shared/news.js                — валидация публикаций
shared/news-html.js           — HTML статей, ленты и sitemap
shared/page-html.js           — общая шапка, подвал и метаданные внутренних страниц
shared/legal-html.js          — страницы документов из настроек
shared/site-pages.js          — валидация редактируемых документов
shared/page-content.json      — начальные тексты документов
shared/site-settings.js        — поля настроек, значения по умолчанию и валидация
shared/site-html.js            — настройки и метаданные в HTML без мигания старых дат
api/application.js            — отправка заявок
public/assets/, public/docs/  — медиа и документы
tests/                        — тесты логики, API и интерфейса
```

`dist/` — результат сборки, `node_modules/` — установленные зависимости. Их не редактируют вручную и не хранят в Git. Даты, цены, контакты и другой изменяемый контент редактируйте в админке. Структура секций и постоянные описания остаются в `src/sections/`. Источники исходных изображений описаны в `docs/image-sources.md`.

## Существующие замечания к контенту

- Положение остаётся черновиком: в нём есть незаполненные фрагменты. На сайте указаны 2–5 июля 2027 для поездки и 3–4 июля для конкурса. Даты и программу можно менять в админке; каждое событие вводится с новой строки, важное примечание — в отдельном поле.
- Начальный состав жюри сохранён из исходного макета; замените его в админке на подтверждённый состав.
- Политика конфиденциальности и согласие на обработку данных требуют проверки владельцем перед приёмом заявок.
