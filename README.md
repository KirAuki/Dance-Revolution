# Танцевальная революция

Сайт конкурса на React и Vite. Сохранены исходный дизайн, адаптивная вёрстка, локальные шрифты, фотографии, видео, документы и серверная отправка заявки.

## Запуск

Нужен Node.js 22.12+ (рекомендуется 24).

```sh
npm ci
npm run dev
```

Откройте адрес, который Vite выведет в терминале. В Windows PowerShell, если запуск npm.ps1 запрещён политикой системы, используйте `npm.cmd ci` и `npm.cmd run dev`.

```sh
npm run build      # production-сборка в dist/
npm run preview    # локальная проверка сборки
npm run check      # тесты валидации/API и сборка
npm run test:e2e   # браузерные сценарии в установленном Google Chrome
```

Для тестов в Edge задайте `PLAYWRIGHT_CHANNEL=msedge`. В PowerShell: `$env:PLAYWRIGHT_CHANNEL = 'msedge'`. Тесты отправки используют заглушки и не отправляют реальные письма.

## Структура

```text
src/
  App.jsx             — порядок секций страницы
  main.jsx            — запуск React
  sections/           — контент и вёрстка каждой секции
  components/         — меню, форма, аккордеон, видео, счётчики
  hooks/              — анимации и настройки уменьшения движения
  styles.css          — исходный дизайн и адаптивные стили
shared/application.js — справочники и общая валидация формы/API
api/application.js    — Vercel Function: отправка писем через Resend
public/assets/        — изображения, видео и локальные шрифты
public/docs/          — положение конкурса для скачивания
privacy.html          — политика конфиденциальности
consent.html          — согласие на обработку данных
docs/                 — источники изображений
tests/                — проверки валидации, API и поведения в браузере
```

`dist/` — только результат сборки: вручную его не редактируют, Vite пересоздаёт папку. `node_modules/` содержит устанавливаемые зависимости. Обе папки исключены из Git. `package-lock.json` фиксирует версии зависимостей для воспроизводимой установки.

Страницы документов остаются обычным HTML и собираются Vite вместе с главной страницей; отдельная библиотека маршрутизации им не нужна.

## Форма и отправка писем

Скопируйте `.env.example` в `.env.local` и заполните:

- `RESEND_API_KEY` — ключ Resend;
- `APPLICATION_TO_EMAIL` — адрес получателя заявок;
- `APPLICATION_FROM_EMAIL` — отправитель на подтверждённом в Resend домене.

Перезапустите dev-сервер после изменения переменных. Секреты доступны только серверному обработчику; не добавляйте им префикс `VITE_`.

`npm run dev` и `npm run preview` обслуживают `/api/application` тем же обработчиком, что Vercel. Без ключа сервер вернёт понятную ошибку настройки; форма сохранит введённые данные. Для реальной отправки нужен настроенный почтовый сервис. Форма принимает 5–500 участников, хронометраж 00:01–04:00, требует все согласия и список проживающих при выборе проживания.

Заявка передаётся двумя письмами: Оргкомитету и заявителю. Базы данных и административной панели в проекте нет. Перед публичным приёмом заявок настройте ограничение частоты запросов `/api/application` на стороне хостинга: скрытое поле ловит лишь простых ботов.

## Публикация на Vercel

Импортируйте проект, выберите Vite и задайте три серверные переменные из `.env.example`. Команда `npm run build`, каталог `dist` и защитные заголовки настроены в `vercel.json`. API остаётся в корневой папке `api/` и разворачивается отдельно от статических ресурсов.

При смене домена обновите canonical в `index.html`, `public/robots.txt` и `public/sitemap.xml`. Простая загрузка `dist/` на статический хостинг покажет страницы, но для отправки заявок понадобится отдельно подключить `/api/application`.

## Изменение содержимого

Тексты и цены меняйте в соответствующем файле `src/sections/`, контакты — в `src/components/Footer.jsx`, поля и поведение заявки — в `src/components/ApplicationForm.jsx`. Списки допустимых значений и ограничения находятся в `shared/application.js`. Изображения и видео можно заменить в `public/assets/`, сохранив имена файлов.

Происхождение изображений описано в `docs/image-sources.md`.
