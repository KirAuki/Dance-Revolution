# Танцевальная революция

React + Vite для интерфейса, Python / Flask для API и страниц новостей и документов. Production: **REG.RU Host-0, ispmanager, Passenger и MySQL 8**. Node.js на хостинге не нужен: JavaScript и CSS собираются на компьютере.

## Запуск на компьютере

Нужны Python 3.12+ и Node.js 24+. В Windows:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
npm.cmd ci
```

На Linux/macOS используйте `python3 -m venv .venv` и `.venv/bin/python`. Скрипты npm находят Python в `.venv`; другой путь можно задать переменной `PYTHON`.

Для **существующего проекта** перенесите данные из прежней SQLite:

```sh
npm run db:import -- .data/site.sqlite
npm run dev
```

Это однократный импорт в новую `.data/site-python.sqlite`. Исходная база сохраняется. Новости, настройки, загруженные файлы и логин с паролем переносятся; старые сессии завершаются. Если импорт уже выполнен, запускайте только `npm run dev`.

Для нового сайта:

```sh
npm run db:init
npm run admin:create
npm run dev
```

Разработка: адрес Vite выводится в терминале, обычно `http://127.0.0.1:5173`. Python API работает на `127.0.0.1:3000`. Просмотр готовой сборки: `npm run build`, затем `npm start`, адрес `http://127.0.0.1:3000`. На рабочем хостинге сервер запускает Passenger, а не эти команды.

`.env.example` содержит настройки MySQL и SMTP. Скопируйте его в `.env.local` для разработки или в `.env` на хостинге. Без MySQL локально используется SQLite; **в production запуск без MySQL запрещён**. Пустой SMTP не мешает сохранять заявки и редактировать сайт.

## Админка

- `/admin/` — новости: черновики, фотографии, предпросмотр, публикация и снятие с публикации.
- `/admin/applications` — заявки: поиск по номеру, коллективу, городу и e-mail; статусы, внутренние заметки, полная карточка, состояние уведомлений и выгрузка CSV.
- `/admin/settings` — редактор сайта: поиск блока и редактирование одного раздела за раз. Изменения хранятся в форме при переключении блоков и публикуются кнопкой «Сохранить настройки».

В настройках редактируются даты и сроки, город, цены и премии, площадка, гостиница и фотографии, программа, жюри, контакты и социальные сети, положение, правовые страницы и оформление новостей. Дополнительно доступны тексты первого экрана, заставка видео, описание проекта, фотография и карточки формата, номинации, возрастные и профессиональные категории, критерии оценки, награды, премиальные номинации, состав услуг, бегущая строка, название организатора и ограничения формы заявки.

Списки номинаций, возрастов и уровней используются одновременно на главной и в форме. Минимум/максимум участников и хронометраж проверяются и в браузере, и сервером. `{awardDate}` и `{minParticipants}` в карточках формата подставляют актуальные значения. Число карточек наград фиксировано композицией, их содержание редактируется.

В документах `{email}` и `{phone}` подставляют текущие контакты, `{privacy}` и `{regulations}` — ссылки. Текст документов и статей — обычный текст без HTML. Пустая строка разделяет абзацы. Файлы: изображения JPG/PNG/WebP до 2 МБ, положение PDF/DOCX до 10 МБ. Видео загружается файлом при развёртывании, а не через редактор.

Правки дат не переписывают содержимое загруженного PDF/DOCX: актуальное положение нужно загрузить отдельно. При конфликте двух вкладок сохранение устаревшей версии отклоняется. Перед закрытием несохранённой формы появляется предупреждение. После истечения сессии введённые значения сохраняются в открытой вкладке до повторного входа.

## Заявки и уведомления

Заявка, зафиксированные на момент подачи даты/цены/согласие и два письма записываются **одной транзакцией**. Успех формы означает сохранение в базе. Повторный запрос с тем же ключом отправки возвращает прежний номер; изменённые данные с этим ключом отклоняются. Действуют постоянные лимиты частоты запросов для IP и e-mail.

Письма оргкомитету и заявителю отправляет отдельная команда:

```sh
python -m backend.cli send-mail
```

В production добавьте её в cron каждую минуту. При сбое почты записи остаются в базе, отправка повторяется до 8 раз. После исправления SMTP окончательно неудачные письма возвращаются в очередь командой `python -m backend.cli retry-mail`. Возможен повтор письма при неоднозначном ответе SMTP; заявка при этом не дублируется.

Заявки доступны только после авторизации. CSV экранирует значения, которые Excel может принять за формулы. Данные заявителя не публикуются в публичных API и не записываются в журналы ошибок. Статусы и заметки внутренние, их изменение не отправляет дополнительных писем.

## Развёртывание

```sh
npm run release
```

Готовый архив появляется в `release/host0-ДАТА-ВРЕМЯ.zip`. Код Python расположен отдельно от публичных файлов. База, `.env`, пароли и uploads в архив не входят.

Основной домен — `dancesrevolution.ru`. В архиве `public/` предназначена для его корня, `redirect-com/` — для отдельного сайта `dancesrevolution.com`, который перенаправляет посетителей на `.ru`. Админка и MySQL общие. Серверный `.env.example` в архиве уже содержит основной адрес; локальные настройки разработки остаются отдельными.

**Пошаговая инструкция:** [REG.RU Host-0](docs/hosting-reg-ru.md). В ней описаны MySQL, Python-окружение, Passenger, импорт старой базы, SMTP, cron, перезапуск и резервные копии. До загрузки архива нужно создать базу и настроить домен в своём аккаунте REG.RU.

При первом размещении на хостинге переносите актуальную `.data/site-python.sqlite` и `uploads/`: импорт в пустую MySQL сохраняет также локальные заявки и состояние писем. Старая `.data/site.sqlite` нужна только для первоначального перехода с Node и не содержит последующих правок.

## Проверки и обслуживание

```sh
npm run check          # Python API + JS validation tests + production build
npm run test:e2e       # browser checks in installed Google Chrome
npm run admin:password
python -m backend.cli cleanup
```

Тесты используют временные базы и не отправляют реальные письма. Проверки Python покрывают сохранение и конкурентные повторы заявок, права доступа, CSRF, конфликты изменений, CSV, загрузки, SMTP-сбои и импорт старой SQLite. Браузерные проверки запускают Python API и Vite самостоятельно.

Данные локально: `.data/site-python.sqlite`, `.data/uploads/`. Старый `.data/site.sqlite` после переноса остаётся резервным источником. На хостинге данные находятся в MySQL и каталоге `DATA_DIR/uploads`. При обновлении сохраняйте базу, загрузки и `.env`; импорт повторно не запускайте. `backend.cli cleanup` удаляет только истёкшие сессии и счётчики лимитов, заявки остаются.

## Структура

```text
backend/          Python API, MySQL models, HTML templates, CLI, mail worker
src/              React website and admin interface
shared/           shared JSON settings, block schemas, browser validation
deploy/host0/     Passenger entry point and Apache configuration
scripts/          local development and Python launch helpers
tests/            Python, JavaScript and browser checks
public/           assets and initial regulations document
docs/             hosting instructions and asset sources
```

Изменение значений по умолчанию в `shared/` не перезаписывает уже сохранённые настройки. Редактируйте работающий сайт через админку. Секреты базы и почты храните только в непубличном `.env`.
